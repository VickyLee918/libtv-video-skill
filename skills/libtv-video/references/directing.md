# 导演工作手册

承接原版第0–9、15–17节中的通用导演方法，执行接口按 LibTV 改写。总原则：能在故事、提示词或素材检查阶段发现的问题，在花积分生成前解决。总导演负责文案、分镜、配色、全部提示词、素材核对与后期；LibTV 模型负责正式生成，用户选择方向、确认画风、确认每次费用并观看/试听。程序色块只作预演，不冒充正式生成画面。

## 1. 开工、关卡与档案

- 从上下文确认总时长、默认或指定画幅、用途/受众、预算、参考片、配色喜好、配乐/旁白/字幕。配歌需要可用的原曲文件和长度，BPM可测，不要求用户先知道。
- 故事未确认不生成图；画风未确认不生成其他正式镜头；每镜素材与提示词审核通过后报本次积分，用户确认才提交。已有授权资产可直接检查利用，不为走流程重新生图。
- 单镜头测试也需要清楚的一句话画面与动作；不要强行扩成多镜头长故事。现有产品素材不等于需先新生成设定图。
- 项目资料按入口规定的目录保存；新增 `continuity.md` 记录连戏，`palette_v1.md` 记录配色，`tasks.csv` 对应远端节点与本地版本。用户指定已有画布时接续，不强制创建新画布。每版新文件/新节点，保留旧素材和成片。
- 本地工具检查按实际使用阶段进行：Python、ffmpeg/ffprobe；草图/帧检查用 numpy、Pillow；处理需求确需时再检查 OpenCV、librosa。输出保存在当前项目，可下载的产物应交付给用户。

## 2. 故事开发

从用户的一句话展开成完整故事，再经确认发展分镜。优先考虑镜头可分别成立的片段式结构，连贯叙事需更严格的连戏；用户指定连贯故事时按要求设计。

1. 写清一句话主题、想传达的情绪或产品卖点，避免只有画面堆砌。
2. 前两秒安排抓人点，写明何时出现什么；后文的画面或动作兑现开头的期待。
3. 每个转折核对原因：物件从哪里来、手能否够到、重量/惯性/空间是否可信。
4. 喜剧或情绪反应可拆为“问题 → 主角解决 → 旁人反应”，反应分先后，避免所有人同秒做同一动作。

可拍性预检：多人交叉走位、手持极小物件、镜子/倒影、左右不对称配饰或发型、同镜换光、一个人连做多动作、俯拍遮脸和过多配角更容易失控。按故事需要简化或拆镜，不把这些题材一律禁止。画面内必须准确的文字优先留后期；配歌时把剧情转折对副歌、关键动作对重拍。
5. 检查可生成性：交叉走位、手拿小物、镜子反射、不对称饰品、单镜换光、连续复杂动作、俯拍遮脸、多配角都容易失败。先调整表演/机位/分镜，不承诺提示词能消除所有缺陷。
6. 配歌时把故事转折对副歌、关键动作对重拍，拍点从原曲取得。

## 3. 分镜表与镜头语言

故事定稿后每镜一行：

| 字段 | 记录要求 |
|---|---|
| 镜号/版本 | S01、S02，关联提示词与素材 |
| 片中时间 | 起止秒数；MV可附小节/拍点 |
| 生成时长 | 遵从模型可选值，尽可能留约0.5秒剪辑余量；不得自行增加用户已锁定的测试时长 |
| 景别/机位 | 大远景、远景、全身、中景、中近景、特写、大特写；平视、仰俯、背后、过肩、遮挡取景 |
| 运镜及原因 | 固定、推近、拉远、跟拍、环绕等，说明为何这样移动 |
| 走位/表情 | 画面左/右、进出画、面向、动作起终点、情绪变化 |
| 运动来源 | 摄影机、人物、焦点、光线或环境；静止也须有叙事理由 |
| 转场/声音 | 与下一镜的连接、对白、音效、配乐位置 |
| 输入模式/素材 | 首帧、尾帧、多参考的实际槽位、用途及顺序 |

有参考片先查看关键帧和节奏，量出景别、主体占比、进出画位置及发生时间。记录学到的是机位、光线还是剪辑，不仅写“同款高级感”。没参考时交替景别和角度，避免全片同样的正面半身；原版“正面最多两次”作为长片段的构图提醒，不套用于单镜产品测试。38%/62%可作头眼构图参考，居中产品展示等需求优先。

每镜说明什么在动，避免无目的漂移。固定机位可让人物或环境运动；需要安静的镜头允许静止，不凭空添加背景路人/道具。摄影机运动服务信息揭示、跟随或特写，避免仅为炫技而环绕。

## 4. 配色、草图与画风确认

- 用户没指定配色时提供2–3种方向，每种给背景、中间调、亮部、强调色、肤色基准及情绪说明。
- 每场列背景/主体/强调色的色号，说明强调色归属；跨镜保护产品色、品牌标签与肤色。
- 付费正式图前先做色块预演：读取本技能 `scripts/colorboard.py` 的 JSON 规范，以脚本完整路径执行。输出彩色 `board.png`、灰度 `board_gray.png`、`contrast.json` 及逐镜图。
- 灰度检查主体与背景，脚本使用的 L* 差20是提醒阈值，结合实际画面判断。脚本画布固定1920×1080，竖屏项目要另按9:16检查主体占比和安全区域，不将横版草图当竖屏效果证明。
- 草图缺脚本时可用程序画构图色块；正式图片仍经 LibTV 实际可用模型生成或采用用户素材，每次付费生成先报价确认。
- 角色设定、场景设定及1–2张代表样帧先确认画风，再做其余正式镜头。

## 5. 视频、静态图与参考提示词

视频公式：**主体 → 场景 → 动作及物理因果 → 景别/运镜 → 时间分段 → 结束/转场 → 声音 → 风格/光线**。

- 4–5秒以一件主要动作作为起点；约8秒以上可按 `0–3s / 3–6s / 6–10s` 分段，每段一件主动作，按实际时长调整。
- 写原因与结果：为什么移动、手在哪里、接触后发生什么、布料/水/灰尘如何响应。
- 重复角色用固定的身份/外观描述块，不依赖跨次生成记忆。已有身份参考图时同时说明其用途，避免文字和图矛盾。
- 不同时写固定与环绕；空间要稳定时慎用摇镜。必要时拆镜剪辑。
- 写“画面左侧”“走向镜头”，避免“他的左边”“往前走”的歧义。
- 一个提示词以一种语言为主，对白用引号标明目标语言、说话人和语气。
- 失败约束要具体，如只有一个杯子、泵头不按压、产品不复制；负面输入框存在时才分开填，不编造字段。
- 开头两秒可选：极近景拉开、动作中途切入、物体飞入、静止突动、异常画面、甩镜揭示、产品反光、前后对比、音效配强动作。按内容选择，不机械堆叠。

静态图公式：**机位/景别 → 谁在画面何处 → 每只手/道具状态 → 背景 → 光线/色表 → 限制**。

- 数量明确，如一瓶、两人、两只手；同台人物应在相容平面，避免脚底高度错位。
- 参考图能看到的外观不反复加矛盾文字，重点说明需要变化的部分。要换构图时不要无意将一张成图锁成构图参考。
- 产品任务保留用户提供的品牌/包装，不继承原版“一律禁止 Logo”的限制；不添加无关文字。包装小字需要单独核查，不能保证模型逐字复现。
- 摄影词汇按意图选用：push-in/pull-out、pan/tilt、tracking、handheld、orbit、dolly-zoom、whip-pan、crane、aerial、FPV、steadicam、static-locked；ELS/LS/FS/MS/MCU/CU/ECU、OTS/POV、rack-focus、bokeh。它们是提示词语汇，不是保证存在的 CLI 枚举。
- 风格和光线可参考 cinematic、浅景深、写实、水墨、3D、手绘；golden hour、soft key、rim light、neon、practical、overcast、chiaroscuro。胶片颗粒、2.35:1、24fps属于按需风格，不覆盖默认9:16或已确认的交付参数。

## 6. 模式选择与素材制作

以实时 schema 选择首帧、首尾帧、图片参考、混合参考等模式。首尾帧适于需要明确动作起终点的镜头，图片参考适于借外观重新构图；不能把模型表中的存在当作所有模式都已实测。参考上限、图片/视频/音频能否混用、顺序和冲突从 schema 与节点读回核对，不沿用 Lenmu Avatar 限制。

每张参考标用途：角色脸/服装、产品外观、空间、运镜、节奏、音色。角色三视图或产品三视图是一件事物的多角度，不是多个主体；单图首帧模式需实际符合构图的单帧，不能用三视拼图冒充成片首帧。

制作顺序：设定图（角色正侧面/脸部、服装/发型/配件；场景空景）→样帧→首帧→在首帧基础上只改计划变化得到尾帧。一次完成一镜并检查，再推进下一镜。无画图需求时直接用已确认素材，不另造付费步骤。

LibTV 图片模型和编辑能力需用 `model search --type image`、模型 schema 及 `--help` 查证，再建 `image` 节点，不调用 Lenmu 的 `edit_image`。局部编辑只在模型真正支持区域控制时使用，不能承诺框外绝对不变。生成后比较未计划改动的背景/产品/身份；反复修图导致浓色锐化时，从正确原版本重新开始。

## 7. 首尾帧检查与连戏

有两帧时执行 `scripts/framecheck.py first.png last.png 输出目录`（完整脚本路径），查看 `overlay.jpg`、`diff.jpg`、`grid.txt`、`phone.jpg`、`zoom_*.jpg`。尺寸不一致即使脚本缩放比较也要记录；差异热图不能替代视觉检查。

1. 后续动作使用的东西必须已在首帧出现，不许杯子/产品凭空冒出。
2. 他人反应需要首帧已安排在同一镜可见位置；若需切反应镜就另列分镜。
3. 多人姿势和动作有差异与先后，避免机械同步。
4. 为落点、走位、头顶和手部动作留空间。
5. 风向、阴影和环境物理方向一致。
6. 手机尺寸仍能辨认主体与关键表情。
7. 放大检查多余瓶子、线条、手指、文字/标签畸变。
8. 首尾不应变化的机位、墙色、产品比例、服装与道具一致；有意运镜造成的差异单独解释。

重复角色、场景、产品、道具分别建本地设定卡，保存固定 traits、参考文件、对应节点ID、批准版本。每镜通过参考连接使用，不能假定平台自动携带卡片。连戏表含衣服、发型、手持物、数量/位置、画面侧别、面向和时间/天气；剧集还要保存情绪、伤势、关系状态。

角色库/Avatar 如在 LibTV 有实际可用入口再单独验证，不伪造注册API。身份或合规拒绝时查看真实原因，选平台允许的角色/素材路线或替换素材；不迁移原版为通过识别而使用的眼嘴微马赛克规避流程。真人素材按授权和平台要求处理，合成或马赛克不当作授权证明。

## 8. 生成前只读审核

材料：提示词文件、原尺寸首尾帧或实际参考图、设定卡、分镜、色表、连戏表、前后镜头关键帧、模型模式/参数。下载不了原图才看预览，并记录只看预览。审核步骤只读，不一边修改一边宣布通过。

逐项给通过/不通过及具体问题：

1. 每句提示词与图的位置、画面左右、颜色、人/物数量、服装、标签、表情是否一致？
2. 首尾机位、景别、背景是否相容，计划变化是否清楚？
3. 是否符合设定、配色及前后镜连戏？
4. 动作是否现实、原因是否写出、手/道具接触关系是否合理？
5. 是否容易同步动作、凭空增物、变脸、走反、变形或歧义？
6. CLI 模式、素材顺序、时长、比例、清晰度、数量、声音是否与用户确认一致？

不通过先列要改什么；修正后重审。独立审核有工具且获准时使用，否则当前代理另起一轮复核并标注自查。通过后先报该次真实积分，等待用户确认；审核通过本身不授权花费。

## 9. 常见错误与沟通

故事没确认先画图、配色无灰度层级、首帧缺道具、首尾背景变色、多人同姿势、参考无用途、短镜塞多动作、跨镜角色描述丢失、任务有ID仍重发、可裁剪却整镜重拍、只看抽帧却声称动态/声音正常，均应在相应阶段主动排查。

用户回报问题先列A/B等具体方案、各自效果与已知费用，按用户选定范围修。新付费生成逐次报价确认；一次修一项并给可对比版本。每个进度附画布链接，最终附已看/未看的内容、版本与实际已知花费。

## 10. 原版情绪短片示例的 LibTV 迁移

主题：“再累的一天，也有人帮你留一盏灯。”15秒竖屏可拆成四镜：0–2.5秒雨夜透明伞突然入画；2.5–6秒湿肩女生进入便利店；6–10秒过肩拍店员推一杯热食；10–15秒女生先愣、稍后退、再微笑。各镜生成时长按实时模型支持及剪辑余量选择，不把例子作为必须生成的任务。

S03首帧：过肩竖屏，左侧湿发女生肩膀虚焦；店员在画面约62%处，站在柜台后，双手前方只有一个冒热气纸杯；背景暖白便利店与冷蓝雨夜。尾帧只改变杯子到柜台边缘、店员双手收回。两帧经过检查再建 LibTV 视频节点。

S03视频提示词示例：固定过肩机位。0–2秒店员看向女生并轻轻点头；2–4秒因杯子烫，她只用指尖扶着杯身推到柜台边缘后松开；4–5秒双手收回、嘴角上扬。前景女生肩膀只有呼吸微动，热气向上，始终只有一杯。若模型支持且用户需要，声音是门外雨声、冰柜低鸣、杯子滑动声。产品广告按实际授权包装要求替换物件，不添加虚构卖点。
