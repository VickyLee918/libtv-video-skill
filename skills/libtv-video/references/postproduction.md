# 声音、结果检查、剪辑与交付

承接原版第10–14、17.2节的通用制作与后期方法；CLI 生成/下载实测见 cli.md。以下本地方法按具体任务执行，不暗示多镜剪辑、对嘴或所有音频模型均已在 LibTV 端到端验证。

## 1. 模型与制作路线

默认视频模型及输出设置按 SKILL.md，不自动改用低价 Mini 或降低清晰度。需要试拍可提出成本/质量方案供用户选择，每次生成先报实际积分确认。

- 常规多镜短片：本地故事/设定卡/分镜 → LibTV 图片素材或用户已有资产 →逐镜素材审核→视频节点→下载→本地剪辑。
- 图片：查当前 image 模型/schema，按参考、编辑、尺寸要求选择；原版 Seedream/Nano Banana 名称和限制不当作 LibTV 现有能力。
- 音频：查当前 audio 模型/schema，区分语音、音乐、音效；时长、字数、音色、音频参考和许可按实际返回，生成也逐次确认费用。
- 对嘴/唱歌：先准备并试听确认音频，再核对所选 LibTV 模型是否支持该音频驱动模式与参考要求；不因原版写 OmniHuman 就声称 LibTV 已有同名模型。
- 局部重拍、延长、视频编辑：实时查 schema、输入格式、时长、范围及报价，只有实际支持时才执行。无法确认则用本地剪辑或提出整镜重拍，不能虚构 `reshoot_video` 等调用。

## 2. 音频与说话人像

对嘴先定台词、目标语言、说话人/音色、情绪、语速与停顿。语音/歌曲由用户提供或经确认费用在 LibTV 生成，用户试听确认后再提交动画；不要先做成片再强塞不匹配的台词。

人像示例：胸上半身、稳定柔光、简洁书房背景、固定机位，约10秒。输入一张经确认的人像及音频，以模型真实支持模式执行；提示“自然说话、嘴型对齐、偶尔点头、轻微手势”。两人同框明确只有谁说话、另一人闭嘴听；长段抽查脸、帽子、手持物、服装漂移。字幕可后期加，不让模型承担必须准确的屏幕文字。

默认开启声音只是允许生成音轨。用户要求提示词不变而原文禁音乐/旁白/音效时，先说明可能安静，保留已确认文本。生成后分别检查有无音轨、采样率、声道、时长、平均/峰值音量；这些不能替代试听和对嘴检查。

配歌拍点从未剪辑原曲测定，可用 librosa 或已知BPM推小节，再与音乐变化核对。对白下压配乐，固定增益配适当降噪，末端限幅；不逐段强行动态响度归一化，避免放大安静段杂音。未经实际试听不声称听感、口型正确。

## 3. 每镜结果检查与修复顺序

先用 ffprobe 读实际尺寸、时长、帧率、视频编码、音轨和色彩标记。不能仅用平台标称“1080P”推断下载参数。每0.5秒抽一格并覆盖起止、动作转折和疑似跳切，长片分批查看，不能只检查第一张拼图。

逐格查角色变脸、手/左右变化、道具消失或复制、产品泵头/瓶型、标签、走位、最后突然重置、闪烁及黑帧。手机尺寸看构图，原尺寸看身份与包装小字。对品牌文字有逐字要求时需原包装对照或经授权的后期处理，不将模糊小字判为准确。

疑似硬切可辅助用：`ffmpeg -i input.mp4 -vf "select='gt(scene,0.25)',showinfo" -f null NUL`，PowerShell用 `Select-String pts_time` 提取；保留 info 日志，不加会隐藏 showinfo 的 `-v error`。阈值只是候选检测，需看相邻帧。

问题优先级：

1. 可本地解决：裁坏头尾、变速/停顿、局部遮盖、裁切重构图、小幅调色、补一两帧闪烁。记录修复区间和副作用。
2. 本地不可修：先修改导致问题的图/提示词，重新审核。只重拍问题镜；支持局部视频编辑时可提局部方案，报价确认再做。
3. 不因下载报错、等待时间长或预览不可播放而直接重拍；按 CLI 引用诊断。

每版新文件/新节点。连续修改图导致浓色、过锐时回到正确原图；小区域改变尽量采用真实支持的区域编辑，但不能承诺生成模型框外绝对不变。用户明确需要位图编辑时按当前环境的图像编辑工具要求执行；后期技术合成不能用来绕过平台身份/内容限制。

## 4. 本地剪辑与调色

LibTV 平台内智能剪辑/字幕/工程导出尚未实测，不能把 Lenmu `assemble_film` 的20段/300秒等限制或“免费”照搬。可用 ffmpeg 和本地编辑工具完成常规剪辑；需用户平台接手时再检查 LibTV 实际导入/剪辑能力。

- 用剪辑清单记录源文件及版本、入点/出点、速度、转场、音量、字幕/字卡、目标输出。每段出点不得越过实际时长。
- 统一目标尺寸、SAR、帧率、像素格式和音频规格再拼接；有/无音轨分别处理，不能让某一段缺音轨造成错位。
- 按分镜设计硬切、遮挡切、甩镜或位移转场；必要时为位移加入合适运动模糊。原版8–16子采样、180度快门是制作选项，不对所有镜头强制增加计算。
- 源色彩标记有效时遵从；标记缺失记录不确定并结合可靠来源/观看核对，不凭“首帧像素误差”断定BT.601或一律按BT.601解码。标准SDR输出正确转换及标记BT.709，HDR需另定转换策略，不能仅改标签伪装转换。
- 中间文件尽量无损或高质量（PNG序列/FFV1等），交付再压缩。保护肤色、产品色和强调色；优先小幅亮度/饱和度调整，不无故改色相、加颗粒、柔光、暗角。用户另定风格时从其要求。
- 原素材低于目标分辨率时可提出 Lanczos 放大/轻度锐化方案，说明不增加真实细节；本技能默认1080P不意味自动将每条片降到720P后再放大。竖屏按目标宽高处理，不复制原版横屏1920×1080命令。
- 拍点和转场照原曲/分镜；字幕用准确文本及独立cue时间，检查断行、阅读时长、竖屏安全区域与脸/产品遮挡。
- 每个剪辑点前后至少3帧抽查黑帧、残影、跳色、构图、字幕和声音接续。用户只要求单镜测试时不附加无关剪辑。

## 5. 粗剪、修订与交付

粗剪用于用户看实际运动、节奏、听声音；列出已看帧范围、尚未完整播放/试听的部分。收到问题先列修复选项、费用和影响，一项项修，有效片段继续利用。

交付原片与易播放的H.264/AAC预览版，另有分享体积目标时再按要求压缩（原版CRF23–25、50MB可作起点，须检查效果）。包含画布链接、镜头版本、任务ID、参数、实际时长/尺寸、费用记录和未验证项。不声称下载警告证明无水印；不代替用户发布、充值或购买套餐。

重新剪已有画布素材时按已修订的清单与版本重组，不从原始节点一律从头到尾重剪，避免把已裁掉的问题放回来。保存本地时间线/EDL或工程；LibTV工程导出只有核实支持后才承诺。若源文件/参数丢失，先核对可见节点信息和本地记录，不虚构导出接口。
