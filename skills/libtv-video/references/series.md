# 短剧、互动故事与系列

承接原版第18节的通用创作方法。以下“集/节点/分支/变量”是故事设计数据，不能与 LibTV 画布素材节点或其未验证的互动播放器能力混同。制作各集视频仍使用 LibTV 并逐次费用确认；不调用 Lenmu 的剧本、发布或统计接口。

## 1. 短剧与互动故事图

线性短剧先列每集主题、人物状态、开头抓点、主要转折、结尾悬念及目标时长。互动故事在此基础上建立有向故事图：

- `choice`：一集结束提出2–3个有意义选项，分别指向后续集，可声明变量变化和超时默认选项。
- `next`：播完接后续集。
- `auto`：按已声明变量/条件分流，并有兜底路径；需要可见过场视频时计入素材清单。
- `ending`：明确结局名称与含义。

先让用户确认图、题目/选项、变量初值/变化、条件门槛及结局，之后再做付费图/视频。原版“3–16节点、最多5选择、2–4结局、4变量、加减3以内”是 Lenmu 约束，不作为 LibTV限制；可用其量级帮助控制初稿规模，实际结构按创意与最终承载平台确定。

图必须全部可达、无意外循环、每条分支能到结局；变量先初始化，条件无空洞，默认选择合法。合并后同一集供多条路径共用时，不提仅某分支发生过的事件；若状态差异影响服装、伤势或对白，拆成不同集，再通过条件分流。

选项均应有合理动机与后果，避免只有一个“明显正确”的伪选择；推理题可以计分并以累计状态分结局。题目卡在手机尺寸要读得懂，选项短，按实际字体测试断行；原版“720P每行约11字”只作可读性提醒，不是强制字数。

## 2. 跨集资产与成本

角色/场景/关键道具设定卡供所有集、分支使用。连戏表包含外观、服装、手持物、方向、天气、伤势和情绪状态，合并集开头须与每条入边兼容。每集细分成分镜后沿用 directing.md 的生成前检查，不能跳过审核。

为每集及条件过场/结局列“视频 → 镜头 → 图/音频需求 → 预期成本”；计划总成本不替代每次实际报价确认。超出用户预算时先缩减镜头/复用已批准素材供用户选，余额不足用已有片段粗剪，不充值。

结构较大时拆为系列，明确每部覆盖的故事范围和用户状态如何衔接。共用变量写入项目设计文档，但跨作品保存/带入须由实际承载平台支持；未确认时在新作品开头重建必要状态，不声称 LibTV 可自动跨剧继承。

## 3. 两条可执行的制作路线

**从故事开始：** 当前代理写故事图/逐集脚本→用户确认→设定卡与分镜→LibTV生成图/视频→本地剪成每集成片→交付视频、分支说明与变量表。LibTV script/storyboard 节点如需使用，先查 CLI 帮助和实时 schema，再验证小规模草稿；不要直接假定原版 `write_story`/`split_episode` 一键流程已映射。

**已有素材开始：** 查画布与已下载文件→确认各集素材及修订版本→本地重剪各集→输出故事图和成片对应清单。文件名/镜号/节点ID/剧情集号分别记录，避免同一“节点”词义混淆。

发布前停止在可审阅交付：没有经核实的 LibTV互动托管、条件路由、默认倒计时、嵌入或统计接口时，明确这些未接通。若用户需要真正可点击的互动播放器，作为单独交付确定目标与权限，不偷偷回退到 Lenmu 或另开网站项目。

## 4. 发布、更新与系列封装边界

可以准备集名、封面、简介、片头/结尾卡、分支图和发布素材包。避免“系列第X集”和“互动故事节点第X集”打架，用户可见标题优先用集名。

发布、可见性、公域展示、嵌入、下架、同意声明、系列管理、观看量/选项/结局数据都需核实目标平台能力，并获得用户对应发布授权；出现同意声明给用户看原文，不代替同意。不承诺重新发布一定保留原URL或有可恢复下架，原版这些 Lenmu 行为不照搬。

重剪按已批准时间线和修订文件重组，维护各集版本对应表；已发布内容的更新范围先明确。图或素材变化会影响后续分支时标记受影响集需要复核，而不是未经确认覆盖重写。
